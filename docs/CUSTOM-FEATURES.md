# 独自の表示設定と効果音

## PCの初期デッキ（MisskeyMoon）

2026-11-12追記：初期構成は左からメイン・通知・メンションの3カラム。メンションも標準の330pxとし、デッキメニューの初期位置は右。保存済みの構成やメニュー位置には適用しない。

UI未選択のログイン済み端末では、初回の画面幅が1024pxを超える場合にデッキを選ぶ。それ以下では通常UIを選び、選択を端末へ保存する。既存のUI選択は優先する。デッキプロファイルが未作成のPCにはメインカラムと通知を用意する。メインカラムは可変幅で残りの横幅を使い、ホーム・ローカルなどのタイムライン切替やページ表示に使用する。通知は標準の330px。ナビゲーションをウィンドウで開く設定は初期値オフで、デッキ内のメインカラムに表示する。既存プロファイル（空の構成も含む）や保存済み設定は保持し、利用者が削除したカラムを再生成しない。以後は通常のデッキ操作で追加・削除・幅変更ができる。

設定 → **独自設定**（`/settings/custom`）から変更する。表示設定はMisskeyの既存の設定プロファイルに保存する。DBスキーマ追加はない。表示の色だけを変更し、投稿の公開範囲やアクセス権限は変えない。

## 絵文字

- 本文のカスタム絵文字とリアクションをそれぞれ50〜150%で調整する。
- 本文は100%で3em（stelpolvaの表示に合わせた値）。タイムライン・詳細・返信・投稿プレビューに適用し、著者名などのサイズは変えない。
- リアクションは画像とOS標準絵文字の両方に倍率を適用する。横長絵文字の幅制限も切り替えられる。新しい設定プロファイルでは幅制限はオフ。既存プロファイルの選択は保持する。

## 公開範囲の色

初期値は無効。有効にするとホーム・フォロワー限定・連合なし・指名・自分だけの背景色と濃さを変更できる。指名/自分だけ → フォロワー限定 → 連合なし → ホームの優先順位で色を選ぶ。通常のパブリック投稿はテーマのまま。

## 牙狼通知効果音

追加音源は公開リポジトリに同梱しない。運営者が `packages/frontend/assets/sounds/custom/`（既存環境は `garo/` も対応）へ配置したMP3を、実際のファイル名でビルド時に検出する。未配置の音源は選択肢に出ない。設置方法は [OPTIONAL-SOUNDS.md](OPTIONAL-SOUNDS.md) を参照。既存の音量・ミュート・アクティブ時だけ再生の設定を利用し、音の選択は自動変更しない。

## ドライブ検索・返信元・CW（2026-11-12追加）

- **ドライブ検索**：ドライブの検索欄でファイル名または説明（ALT）の部分一致検索。検索ボタン/Enterで適用し、解除ボタンで通常一覧へ戻す。現在のフォルダー内だけが対象で、サブフォルダーを再帰検索しない。大文字小文字を区別せず、`%`・`_`・バックスラッシュは文字として扱う。本人のファイル、フォルダー、MIMEフィルター、件数/IDページングの制約を維持する。検索語の上限は1000文字。`drive/files` に任意の `searchQuery` を追加しSDKも再生成済み。DB変更なし。
- **返信元の折りたたみ**：設定 → 独自設定 → 投稿の読みやすさ →「返信元の投稿を折りたたむ」。初期値はオフ。タイムラインと投稿詳細で返信元を最初は隠し、各投稿の表示/非表示ボタンで切り替える。設定はプロファイルに保存する。
- **CW一括開閉**：投稿詳細のヘッダーに「会話内のCWをすべて開く/閉じる」を追加。主投稿、会話の返信元、返信、引用に適用する。後から読み込まれた子投稿も現在の指示へ合わせる。個々のCWボタンも引き続き使える。隣接投稿のタイムラインへは波及せず、ページ移動時には状態をリセットする。ミュート・閲覧権限・センシティブ画像・添付や長文の折りたたみは解除しない。

手元のSharkeyの実装を参照し、Misskeyのページング・コンポーネント構造へ合わせて移植した。UI一式の置き換えはしていない。

## 検証

- frontendの型検査と本番ビルド。
- custom-appearanceの5テスト（公開範囲の優先順位、無効時、ホームと連合なし、無効な色/濃さ、倍率の範囲）。
- Vueレビュー実施。プレビューの相対URL問題とOS標準絵文字の倍率問題を修正。
- 起動後のHTTPによる本番JS/CSS・音源配信確認。ブラウザーでの設定保存・見た目・実際の試聴は本人による確認が必要。

Ubuntuでは変更したソースと音源を同期し、i18n・icons-subsetter・frontendをビルドする。通常画面と埋め込み画面の両manifestが必要。設定やDBは移行検証用の構成を継続する。
